# Test Plan — Phase 6 (출고처리)

## 사전조건

- Phase 5 완료 후 주문 A가 `CONFIRMED` 상태 (시료 `S001` 재고 ≥ 주문 A 수량)

## 테스트 시나리오

### TC6-1. CONFIRMED 주문 목록 표시

1. 출고처리 진입
2. 예상 결과: 주문 A가 목록에 표시됨 (번호/주문번호/고객명/시료명/수량)

### TC6-2. 정상 출고

1. 주문 A 선택 후 출고실행
2. 예상 결과:
   - 시료 `S001` 재고가 주문 수량만큼 차감됨
   - 주문 A 상태 `CONFIRMED` → `RELEASE`로 전환
   - `releasedAtEpochSec`, `releasedQty` 기록됨
   - 결과 화면에 주문번호/출고수량/처리일시/상태변경 내역 출력

### TC6-3. 출고 후 목록에서 제외

1. TC6-2 이후 출고처리 목록 재조회
2. 예상 결과: 주문 A가 더 이상 CONFIRMED 목록에 나타나지 않음

### TC6-4. 재고 부족 상태에서 출고 시도 (방어적 케이스)

1. 재고를 인위적으로 주문수량보다 적게 만든 뒤 (예: 다른 주문으로 먼저 재고 소진) 해당 CONFIRMED 주문 출고 시도
2. 예상 결과: 에러 메시지 출력, 상태 변경되지 않음

### TC6-5. 상태전환 로그 기록

1. TC6-2 완료 후 `logs/order_events.log` 확인
2. 예상 결과: 주문 A에 대해 `CONFIRMED`→`RELEASE` 전환 기록이 추가됨

## 완료 기준

- 위 5개 시나리오 모두 통과
- 출고 완료 후 등록→주문→승인→생산→출고 전체 흐름이 처음부터 끝까지 한 번 이상 성공적으로 재현됨

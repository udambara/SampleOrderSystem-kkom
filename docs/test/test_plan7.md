# Test Plan — Phase 7 (모니터링)

## 사전조건

- Phase 6까지 완료된 상태에서 RESERVED/CONFIRMED/PRODUCING/RELEASE/REJECTED 각 상태의 주문이 최소 1건씩 존재

## 테스트 시나리오

### TC7-1. 주문량확인 — 상태별 집계

1. 모니터링 → 주문량확인 진입
2. 예상 결과: RESERVED/CONFIRMED/PRODUCING/RELEASE 각각의 건수가 실제 `data/orders.json`과 일치하도록 표시됨

### TC7-2. 주문량확인 — REJECTED 제외

1. TC7-1 화면에서 REJECTED 주문 존재 여부 확인
2. 예상 결과: REJECTED 건수는 집계/표시에 포함되지 않음

### TC7-3. 재고량확인 — 상태 표기 (재고 대비 미출고 수요 기준)

1. 시료 재고 0개인 케이스 준비 → 모니터링 → 재고량확인 진입 → "고갈" 표기 확인
2. 시료 재고 170개 준비 → 수량 130 주문을 접수 후 승인(재고 충분이므로 승인 즉시 재고에서 130 차감되어 재고 40으로 표시됨, 상태는 `stockDeductedAtApproval=true`) → 재고량확인 진입 → 재고 40, "여유" 표기 확인 (해당 주문은 이미 차감 반영되어 수요 계산에서 제외됨)
3. 위 상태에서 동일 시료로 RESERVED 주문 90개를 추가 접수(승인하지 않음) → 재고량확인 재진입 → 재고는 그대로 40이지만 상태가 "부족"으로 바뀜을 확인 (40-90=-50)

## 완료 기준

- 위 3개 시나리오 모두 통과
- 재고 상태가 고정 임계값이 아니라 재고와 미출고(RESERVED+PRODUCING+생산을 거친 CONFIRMED) 수요의 차로 정확히 판단됨
- 승인 시점에 재고가 이미 차감된 CONFIRMED 주문은 수요 계산에 중복 반영되지 않음

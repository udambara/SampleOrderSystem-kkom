# Test Plan — Phase 3 (시료주문/예약)

## 사전조건

- Phase 2 완료, 시료 `S001`(실리콘웨이퍼) 등록되어 있음

## 테스트 시나리오

### TC3-1. 정상 예약

1. 시료주문 → 시료예약 진입
2. 시료ID=`S001`, 고객명=`ACME`, 주문수량=`50` 입력
3. 예상 결과: 주문번호(`ORD-YYYYMMDD-0001`) 발급, 상태 `RESERVED`로 저장, 등록 결과(주문번호 포함) 출력

### TC3-2. 같은 날 여러 건 예약 시 주문번호 증가

1. TC3-1 이후 동일한 날 다시 예약 진행 (시료ID=`S001`, 고객명=`Globex`, 수량=`10`)
2. 예상 결과: 주문번호가 `ORD-YYYYMMDD-0002`로 발급됨

### TC3-3. 존재하지 않는 시료ID로 예약 시도

1. 시료ID=`S999`(미등록)로 예약 시도
2. 예상 결과: 에러 메시지 출력, 주문이 저장되지 않음

### TC3-4. 잘못된 주문수량 입력

1. 주문수량=`0` 또는 음수 입력
2. 예상 결과: 에러 메시지 출력, 주문이 저장되지 않음 (재입력 또는 취소)

### TC3-5. 상태전환 로그 기록

1. TC3-1 예약 완료 직후 `logs/order_events.log` 확인
2. 예상 결과: 해당 주문번호에 대해 `-` → `RESERVED` 전환 기록이 시각과 함께 추가됨

## 완료 기준

- 위 5개 시나리오 모두 통과
- `data/orders.json`에 TC3-1, TC3-2 주문이 `RESERVED` 상태로 정확히 저장됨

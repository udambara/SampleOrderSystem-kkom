# Review — Phase 6

## 피드백

출고처리에서 주문 선택 프롬프트가 `출고할 주문 번호 (0=취소, 1~4): `로 표시되는데, 이 표기가 마치 "1부터 4까지 범위로 입력할 수 있다"는 것처럼 보여서 사용자가 실제로 `1~4`를 입력했다. 하지만 기존 구현은 `std::cin >> choice`로 정수 하나만 읽었기 때문에 `1~4` 입력 시 `1`만 파싱되고 나머지(`~4`)는 버려져, 의도와 다르게 주문 1건만 출고되었다.

사용자는 "하나씩 입력을 받던지, 아니면 복수도 허용할 수 있게 조정하든지" 요청했고, CONFIRMED 주문을 한 번에 여러 건 출고하고 싶다는 의도였다.

## 조치

- `ConsoleView::ReadIndexChoices(count, prompt)` 신규 추가 — 단일 번호(`1`), 콤마로 구분한 여러 번호(`1,3`), 범위(`1-3` 또는 `1~3`)를 모두 파싱해 유효한 인덱스 집합을 반환. 프롬프트 문구에도 "여러 건은 쉼표 또는 -로 구분 입력. 예: 1,3 또는 1-3"을 명시해 다시는 오해가 없도록 함
- `ShippingController::HandleRelease()`가 선택된 인덱스를 순서대로 순회하며 각각 독립적으로 출고 처리 — 특정 건이 재고 부족 등으로 실패해도 에러만 출력하고 나머지 건은 계속 진행 (배치 전체가 중단되지 않음)
- 이번 변경은 출고처리(Phase 6)에만 적용했고, 동일한 단일선택 프롬프트를 쓰는 승인/거절(Phase 4)은 이번 요청 범위가 아니라서 그대로 둠

## 검증

- 재빌드 성공
- 사용자가 보여준 것과 동일한 시나리오(CONFIRMED 4건: 하이닉스 20/20, 삼성 100, 엔비디아 200)를 재현해 `1-4` 입력으로 4건이 순서대로 처리되는 것을 확인
- 배치 도중 재고가 부족해진 건은 해당 건만 에러 메시지 출력되고, 나머지 건은 정상적으로 계속 출고 처리됨을 확인 (부분 실패가 전체를 막지 않음)

# Review — Phase 1

## 피드백

콘솔에서 메뉴 텍스트가 깨져서 출력됨:

```
===== 諛섎룄泥??쒕즺 愿由??꾨줈洹몃옩 =====
1. ?쒕즺愿由?
2. ?쒕즺二쇰Ц
...
```

## 원인

- 프로젝트에 `/utf-8` 컴파일 옵션을 적용해 소스/실행 문자 집합을 UTF-8로 고정했음 (BOM 없는 UTF-8 소스 파일이 MSVC 기본 코드페이지(949)로 잘못 해석되어 빌드 자체가 깨지는 문제를 막기 위한 조치, `docs/review` 도입 이전에 이미 반영됨)
- 그 결과 실행 파일 안의 한글 문자열 리터럴은 UTF-8 바이트로 저장되지만, Windows 콘솔의 출력 코드페이지가 UTF-8(65001)이 아니라 시스템 로케일 코드페이지(한국어 Windows 기본값 949)로 남아있으면 그 UTF-8 바이트를 949로 잘못 해석해 깨진 글자로 출력됨
- 즉 "빌드 시 문자 인코딩"과 "콘솔 출력 코드페이지"가 서로 어긋나서 발생한 문제

## 조치

`src/main.cpp`에서 프로그램 시작 시 콘솔 입출력 코드페이지를 UTF-8로 강제 설정하도록 수정:

```cpp
#ifdef _WIN32
SetConsoleOutputCP(CP_UTF8);
SetConsoleCP(CP_UTF8);
#endif
```

## 검증

- 재빌드 성공 (경고/에러 없음)
- 리다이렉션된 입출력(파일 기반) 테스트에서는 원래도 문제가 재현되지 않았음 — 콘솔 코드페이지는 대화형 콘솔 렌더링에만 영향을 주기 때문. 이번 수정은 실제 대화형 콘솔(cmd/PowerShell/Visual Studio 디버그 콘솔)에서 확인이 필요함
- 이 환경의 기본 콘솔 코드페이지가 이미 65001(UTF-8)이라 로컬에서 깨짐 현상 자체를 재현하지는 못했지만, 증상(UTF-8 바이트를 CP949로 오독한 전형적인 한글 깨짐 패턴)과 원인이 명확히 일치하여 표준적인 해결책(`SetConsoleOutputCP(CP_UTF8)`)을 적용함

## 후속 확인 필요

- 사용자 환경(콘솔 코드페이지가 949인 환경)에서 재빌드 후 직접 실행하여 메뉴가 정상적으로 표시되는지 확인 필요

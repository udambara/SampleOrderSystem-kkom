# Review — Phase 4

## 발견된 버그

Phase 4 시나리오를 수동 테스트하던 중, 테스트 입력 스크립트의 메뉴 선택 횟수가 실제 필요한 횟수보다 적어서 표준입력이 EOF에 도달하는 상황이 발생했다. 이때 프로그램이 종료되지 않고 무한 루프에 빠져 CPU를 계속 사용하며 멈춰 있었다.

### 원인

`ConsoleView::ReadMenuChoice`/`ReadIndexChoice`의 입력 검증 루프는 `std::cin`이 실패 상태가 되면 `std::cin.clear()`로 에러 플래그만 지우고 재입력을 요청했다. 그런데 원인이 "잘못된 값"이 아니라 "입력 스트림이 끝남(EOF)"인 경우, `clear()`를 해도 다음 읽기 시도가 즉시 또 실패하고 EOF 상태가 그대로 반복되어 루프가 영원히 끝나지 않았다.

이 버그는 Phase 1부터 존재했지만, 그동안 테스트 스크립트가 항상 정확한 개수의 입력을 제공해 EOF에 도달한 적이 없어 드러나지 않았다. Phase 4 테스트에서 승인/거절 후 목록이 줄어드는 것을 고려하지 못하고 입력 개수를 잘못 맞추면서 처음으로 재현되었다.

## 조치

`src/ConsoleMVC/ConsoleView.cpp`에 `ExitOnEof()` 헬퍼를 추가하고, `ReadMenuChoice`/`ReadIndexChoice`의 재시도 루프 안에서 재입력을 요청하기 전에 `std::cin.eof()`를 확인하도록 수정했다. EOF가 감지되면 재시도하지 않고 `std::exit(0)`으로 즉시 정상 종료한다.

## 검증

- 재빌드 성공
- 의도적으로 입력을 부족하게 준 재현 테스트에서, 수정 전에는 무한 루프(타임아웃)로 멈췄던 것이 수정 후에는 EOF 시점에 깔끔하게 종료됨(exit code 0)을 확인
- 이후 Phase 4의 정상 시나리오(TC4-1~TC4-6: 목록 조회, 재고 부족/충분 승인, 대기열 등록, 거절, 로그 기록)를 올바른 입력 순서로 재실행해 모두 통과 확인
